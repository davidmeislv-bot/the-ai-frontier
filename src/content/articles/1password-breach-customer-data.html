Password manager 1Password says hackers broke into its internal systems and took customer account records, but did not reach the vaults where passwords live.

The Toronto-based company disclosed the breach on Wednesday. It began investigating on November 19, after spotting signs that an employee's corporate GitHub account had been compromised. The attacker used that account to reach private source code and push malicious code into 1Password's backend services, which then downloaded customer records.

The records taken include names, the email addresses customers use to sign in, account and user IDs, and the dates accounts were created and last used. The attacker also took public keys, protocol parameters used to verify logins, and tokens embedded in emailed links for invitations, provisioning and account recovery. Source code was copied as well, and the attacker reached the company's build and deployment system, which holds infrastructure credentials. 1Password says the source code holds no user secrets, and it has rotated the infrastructure credentials.

What the attacker did not get, according to the company, is the part that matters most. 1Password wrote: "Your vault data, the items in them, and the keys that protect them are safe and were not affected." The company says it has no access to customer passwords or the secret keys that scramble them, so those could not have been taken.

1Password has disabled the compromised GitHub account, revoked the stolen token, and hardened its GitHub, build and device controls. It also lengthened invitation and recovery codes from six digits to ten letters and numbers, and brought in outside cybersecurity experts to check its response. One question remains open: the company has not said how many customers had records taken. 1Password says it is in the process of notifying customers, and a small number of users with outstanding provisioning or recovery invitations were specifically notified.
